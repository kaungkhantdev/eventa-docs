# Dead-letter handling — diagram sources

The drawing behind
[devops-observability-sre.md §8.1](../devops-observability-sre.md#81-dead-letter-handling), covering
**what a person does with a message once it has parked** in `eventa.worker.dlq`: notice it, inspect it
without consuming it, classify the failure, then replay or drop, and verify. The path that *leads* to
the parking queue — the exchange, the work queue and the four retry rungs — is the diagram in §8.1
itself; this one begins where that one ends.

| File | What it is |
|---|---|
| `dead-letter-handling.mmd` | **Source of truth.** Mermaid flowchart; edit this one. |
| `dead-letter-handling.png` | Rendered from the `.mmd` — 1924 × 2368, 2× scale. |
| `dead-letter-handling.tldr` | tldraw v5 canvas, for editing the diagram on a canvas offline. |

As everywhere else in this repo, the `.png` and `.tldr` are **derived artifacts that go stale
silently**: editing the `.mmd` updates neither, and editing the `.tldr` updates nothing at all.
Regenerate rather than hand-reconciling.

## Regenerating the PNG

No toolchain is committed, and `mmdc` is not installed — but any local Chrome renders it. From this
directory:

```bash
S=$(mktemp -d)
{ printf '%s' '<!doctype html><meta charset="utf-8"><style>html,body{margin:0;padding:20px;background:#fff;font-family:-apple-system,system-ui,sans-serif}</style><pre id="d" class="mermaid">'
  cat dead-letter-handling.mmd
  printf '%s' '</pre><script type="module">import m from "https://cdn.jsdelivr.net/npm/mermaid@10.9.1/dist/mermaid.esm.min.mjs";m.initialize({startOnLoad:false,securityLevel:"loose",flowchart:{htmlLabels:true,curve:"basis"}});await m.run();const s=document.querySelector("#d svg"),v=s.getAttribute("viewBox").split(" ").map(Number);s.style.maxWidth="none";s.setAttribute("width",v[2]);s.setAttribute("height",v[3]);</script>'
} > "$S/r.html"
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --allow-file-access-from-files --virtual-time-budget=15000 --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=962,1184 \
  --screenshot="$PWD/dead-letter-handling.png" "file://$S/r.html"
```

`--window-size` is the diagram's own size plus the 20 px padding, so it needs adjusting whenever the
flowchart grows: the render prints its natural size in the SVG `viewBox`.

## Regenerating the `.tldr`

There is no converter — the file was generated by templating the record schema off
`../devops-observability-sre.tldr` (`document` + `page` + `geo`/`arrow` shapes + two `binding` records
per arrow, one per terminal). If the flowchart changes substantially, it is less work to redraw the
canvas in tldraw and export than to patch the JSON by hand.
